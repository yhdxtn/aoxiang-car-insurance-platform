# 泰康车险报价小程序系统 · 独立源码交付

本项目依据本次上传的需求概要、报价页面参考图和泰康接口源码重建。它是**独立的小程序业务系统**：使用自己的 Java 后端、MySQL 数据库、管理网页和客服网页。仅接入泰康车险报价；摩托车走人工，其他保险公司及企业微信群机器人不进入新系统。

## 1. 四部分源码

| 目录 | 内容 | 本地开发入口 |
|---|---|---|
| `miniprogram` | 原生微信小程序，JS/WXML/WXSS；微信开发者工具直接导入 | 工具导入该目录 |
| `backend` | Java 21 / Spring Boot 3.5.16 / JDBC / Flyway / MySQL | `18080` |
| `apps/admin-web` | Vue 3 网页后台，按角色显示菜单与组织范围 | `5173` |
| `apps/service-web` | Vue 3 独立人工客服工作台 | `5174` |
| `services/taikang-gateway` | 后端配套的私有泰康协议适配器，复用原 Python 登录及报价代码 | 私有 `18081` |
| `deploy`、`scripts`、`docs` | 部署模板、启动脚本、需求映射、API 合同、验收记录 | 见下文 |

所有前端只访问 Java `/api/v1`。小程序不存泰康密码、微信 AppSecret 或 OCR API Key。Java 统一执行身份、组织数据范围、业务状态与审计检查。

## 2. 已完成的业务

### 小程序

- 首页、订单、我的三个底部导航；普通用户和代理都能使用。
- 按参考图制作的奶油色＋橙色对话式报价页：资料确认 → 方案报价 → 投保确认。
- 相册、拍照、微信聊天三种图片来源；微信群图片由用户在微信原生选择器中主动选择。
- 图片上传、授权预览、可配置图片识别、完整手工填写、车辆资料核对及修改。
- 泰康单方案报价，支持交强、标准方案、含车损方案和保额输入；显示实际保费及险种明细。
- 人工客服会话、历史消息、资料补充、订单查询与状态跟踪。
- 个人账号、角色、组织、政策、积分、代理客户及预估业绩。

### 管理端

- 总部管理员、财务、代理的分角色工作台与数据范围。
- 客户维护、订单查询、人工跟进、核价、保单号登记和操作历史。
- 组织树、下级组织与账号创建、启用/停用及权限变更。
- 总部与各级代理政策版本、有效期、来源及比例约束。
- 按订单冻结政策的预估佣金、积分明细及幂等人工调整、审计日志。
- 泰康配置状态及管理员发起的真实登录检查。

### 客服端

- 独立登录，待接入／处理中／已结束队列，三栏会话工作台。
- 领取、转接、关闭，文字沟通、资料上传、授权查看原图及车辆信息编辑。
- 协助调用泰康报价，展示外部单号和异常状态；摩托车及特殊情况登记人工核查申请。
- 人工保费核实和办理进度登记。未核价显示“待人工核价”，不会当作0元保费。

### 后端保护

- 用户密码使用 BCrypt，登录令牌只保存哈希；个人资料、消息、备注和原图加密保存。
- 用户只能读取本人业务；代理按组织范围读取；客服必须先领取才可改资料，转接后失去原会话写权。
- 报价、订单、消息、积分具备服务端幂等保护；资料修改使旧报价失效。
- 外部调用结果未知时保留原请求，不自动重报；处理中不能关闭会话。
- 演示与正式数据库隔离，未配置真实渠道不会伪造真实报价。

## 3. 先运行演示环境

要求 **JDK 21、Maven 3.9+、Node.js 22+**。演示后端使用本地 H2 文件数据库，不需要先部署 MySQL 或泰康网关。演示金额全部明确标注，不产生真实保单和支付。

在第一个终端启动 Java：

```bash
cd backend
mvn -B package
java -jar target/mini-insurance-api-1.0.0.jar --spring.profiles.active=demo
```

也可以在项目根目录运行 `bash scripts/run-demo.sh`，Windows PowerShell 运行 `./scripts/run-demo.ps1`。

在另外两个终端启动管理和客服网页：

```bash
cd apps/admin-web
npm ci
npm run dev
```

```bash
cd apps/service-web
npm ci
npm run dev
```

浏览器访问 `http://localhost:5173` 和 `http://localhost:5174`。两个网页项目已默认代理 `/api` 到 `http://127.0.0.1:18080`。

| 演示账号 | 密码 | 用途 |
|---|---|---|
| `admin` | `DemoAdmin!2026` | 总部管理端 |
| `service` | `DemoService!2026` | 客服端 |
| `agent` | `DemoAgent!2026` | 代理范围管理 |
| `customer` | `DemoCustomer!2026` | 小程序普通用户流程 |

这些账号仅在 `demo` profile 的新演示数据库中创建。正式环境仅根据你设置的初始密码创建管理员，不自动生成这些公开测试账号。

### 导入微信开发者工具

1. 导入 `miniprogram` 目录，配置你的小程序 AppID。
2. 开发调试时确认 `config.js` 的 `apiBaseUrl` 指向 Java 服务。
3. 开发者工具本机调试可使用 HTTP 本地地址；真机需手机可达地址。正式版必须改成已配置的小程序 HTTPS 合法域名。
4. 本地演示选择“演示账号登录”；正式微信登录需要后台配置 AppID/AppSecret。
5. 在微信平台完成用户隐私保护指引，声明所用图片/文件选择接口；正常体验通过页面隐私授权后再选择资料。

聊天选择通过 `wx.chooseMessageFile({type:'image'})`，相册/相机通过 `wx.chooseMedia`。上传文件上限10MB，格式JPEG、PNG、WebP；取消选择不当作上传失败。

## 4. 正式运行

先生成私有环境文件：

```bash
python3 scripts/generate-env.py
```

它生成独立的数据库密码、管理员初始密码、资料加密密钥和网关密钥，不覆盖已有 `.env`。然后填写：

- 微信：`WX_APP_ID`、`WX_APP_SECRET`。
- 泰康：`TK_USERNAME`、`TK_PASSWORD`、四个承保地区字段；确认账号授权后再启用 `TK_LIVE_ENABLED=true`。
- 数据库：MySQL 8.4 的地址、用户名和密码。
- 域名：管理端、客服端及小程序 API 的正式 HTTPS 地址。
- 可选 OCR：`OCR_BASE_URL`、`OCR_API_KEY`、`OCR_MODEL`。不配置时照常支持手填与人工。

**普通服务器部署与可选 Docker Compose 两种方式均已说明：见 `docs/DEPLOYMENT.md`。** Java 和网关都有 systemd 模板；微信正式版不依赖网页开发服务器。

## 5. 必须明确的业务边界

| 项目 | 当前处理 |
|---|---|
| 家用车 | 复用上传的泰康协议进行真实登录、车型/险种校验及报价；需要有效账号和本笔资料 |
| 货车 | 保留入口和资料链路；原代码固定家用用途，货车协议未完整确认，因此转人工，不冒用家用车字段 |
| 摩托车 | 直接人工，不调用自动报价 |
| 报价后确认 | 创建本系统的投保申请，由客服继续办理；不会自动支付或自动出单 |
| 订单完成 | 人工核实保费及正式保单号后登记，不根据二维码或按钮点击推断已出单 |
| 佣金 | 只按管理端明确配置并下发至该组织的政策估算；没有政策则为0；不等同已结算或可提现 |
| 积分 | 余额、明细、带审计的人工调整；没有猜测积分获取或商品兑换规则 |
| 商品兑换/复杂佣金档位 | 原需求列为待确认，未擅自实现自动兑换、提现或差额分润 |
| 旧系统 | 不迁移旧账号、旧客户、旧企微群和历史保单；新库独立保存业务 |

真实微信、真实泰康、当前账户可承保地区、正式核保和出单需要在你的配置环境完成联调。交付包含实际接口实现和验证记录，**没有把离线模拟结果当作保司实测成功**。
