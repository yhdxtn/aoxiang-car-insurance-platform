## 后端测试的实质覆盖

- 未登录、不同普通用户、不同代理组织之间的资料/会话/订单隔离。
- 私有文件权限与实际加密保存，跨会话图片引用拒绝。
- 客服领取、重复抢占、转接后原客服失去授权。
- 报价版本、资料修改使旧报价失效、订单唯一及并发重复提交。
- 外部结果未知不自动重报，处理中不能关闭，完成回执不会重新打开已关闭会话。
- 角色和组织权限、精确组织政策、历史高比例政策不能绕过新的上级限制。
- 佣金冻结，不因政策变更改写历史订单；未下发到该组织时不继承总部比例。
- 财务角色的证件、手机号/VIN、自由文本业务备注保护。
- 积分重复提交及并发调整，余额与流水一致。
- 摩托车/货车人工流程；家用车异常后人工核查申请。
- 未核价金额null、人工核价权限、自动报价价格不可人工修改、完成需真实保单号登记。

## 网关测试的实质覆盖

- 相同请求复用结果、不同请求内容共用同编号拒绝。
- 请求已登记但进程中断时，重启后不执行第二次外部调用。
- 账本加密、同一实例目录的独占锁和原密钥身份保护。
- 私有接口认证；校验失败不在错误响应回显原图内容。
- 缺少账号/未启用真实模式不返回模拟保费。
- 缺少用途、内外车型不一致、货车、摩托车阻止进入自动家用车协议。
- `loginStatus` 未明确成功时不报告ONLINE，多车型不静默选择第一项。
- 阻止投保和支付路径；按选定方案映射险种和保额，核验返回保费组成。
- 清理HTTP会话时即使发生异常，也不丢失已确认结果、不遗留账户锁。
- OCR未配置、图片真实格式错误及上游异常转手填；有效识别只返回白名单字段。

## 实际遇到的环境限制

本环境允许源码编译和进程内测试，但启动 MySQL 服务或 Chromium 时遇到 `socket() Operation not permitted`。因此采用了以下有明确边界的替代验证：

1. **后端HTTP层**使用 MockMvc，在同一进程内执行实际控制器、认证、服务和数据库操作；不是通过公开HTTP监听端口测试。
2. **数据库语法兼容**使用 MySQL 官方支持的 `--initialize-insecure --init-file` 初始化序列，在全新的临时目录中实际执行迁移并核对表数量。此过程没有连接你现有数据库，亦没有通过JDBC跑全套业务事务。
3. **页面结构**完成 Vue 编译和SSR/静态渲染检查，小程序完成WXML静态检查；没有将静态渲染冒称为微信或Chromium真机行为验证。

- MySQL 8.4 常规启动后的 Java/JDBC 全流程与并发事务验证。
- Docker镜像构建和Compose正常启动（如你选择Docker部署）。
- 管理/客服浏览器完整交互、窗口大小、跨域/反向代理和上传检查。

- 你的泰康账号、实际承保地区、车辆资料、车型候选和当前接口响应联调。
- 配置的 OCR 服务真实识别质量；OCR结果必须由用户核对。
- 人工办理、保单号录入及业务确认后的佣金费基/积分规则。

当前没有执行真实保司报价、支付或出单，不宣称得到正式账号验收或生产压测结果。列表中的搜索部分仍有权限范围内解密筛选，较大业务量需要进一步做SQL分页/搜索索引优化和容量测试。

## 复现

常规测试命令见根README和各子项目README。可选的MySQL纯建表验证：

```bash
python3 scripts/verify-mysql-schema.py --mysqld /实际路径/bin/mysqld --basedir /实际路径
```

脚本只建立并删除一个新的临时数据目录，不操作任何已有数据库。该检查不代替正式部署后的JDBC验收。
